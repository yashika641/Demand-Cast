### *DemandCast User Manual — File Upload Guide (Detailed)*

---

# 🔷 **1. Introduction**

Uploading files is the very first step required to use DemandCast.
The platform is fully data-driven—your sales, inventory, product, pricing, and promotional files form the foundation of every forecast, prediction, and insight the system generates.

This guide explains in detail:

* What files are required
* File formats supported
* How to prepare your files
* How to upload the files inside DemandCast
* How the platform identifies each file automatically
* How to troubleshoot upload issues
* Best practices for consistent results

---

# 🔷 **2. Supported File Types**

DemandCast currently supports:

* **CSV** files (`.csv`)
* **Excel** files (`.xlsx`)

No other formats (PDF, images, JSON, SQL dumps) are accepted.

---

# 🔷 **3. Required Files (Minimum)**

You must upload at least the following files:

| File Name          | Purpose                                                   |
| ------------------ | --------------------------------------------------------- |
| **Sales File**     | Demand forecasting, stockout analysis, promotions insight |
| **Inventory File** | Stockout prediction, inventory simulations                |
| **Products File**  | SKU metadata, reference IDs                               |

---

# 🔷 **4. Optional (But Highly Recommended)**

Uploading these improves model accuracy:

| File Name                    | Impact                                     |
| ---------------------------- | ------------------------------------------ |
| **Promotion / Pricing File** | Promo effectiveness, uplift, discount ROI  |
| **Supplier / Leadtime File** | Leadtime modeling & reliability estimation |
| **Customer File**            | Consumer segmentation & channel analytics  |

---

# 🔷 **5. Naming Your Files (Automatic Detection)**

You **do NOT** need perfect names.
DemandCast uses **automatic regex-based detection**.
Example patterns it can detect:

### **Sales File Keywords**

* sale, sales, demand, order, transaction

### **Inventory File Keywords**

* inventory, stock, soh, onhand

### **Products File Keywords**

* product, sku, catalog, item

### **Customer File Keywords**

* customer, buyers, promo, pricing, campaigns

### **Supplier / Leadtime File Keywords**

* supplier, vendors, vendor, leadtime

As long as your filename contains one of these keywords, the platform will correctly route your file.

---

# 🔷 **6. Preparing Your Files Before Upload**

## ✔ 6.1. Remove merged cells

Excel files with merged cells cause parser errors.

## ✔ 6.2. Ensure header row exists

Row 1 must contain column names.

## ✔ 6.3. Remove formulas

Convert formulas to values.

## ✔ 6.4. Ensure date formats are valid

Recommended formats:

* `YYYY-MM-DD`
* `DD/MM/YYYY`
* Excel serial dates also accepted.

## ✔ 6.5. No empty rows at the top

Avoid blank rows before the header.

## ✔ 6.6. No commas inside numeric fields (CSV)

“1,234” becomes “1234”.

# 🔷 **8. How DemandCast Stores Your Uploaded Files**

Uploaded files are logged inside the database:

### **Table: user_files**

| Column      | Description         |
| ----------- | ------------------- |
| user_id     | Your user ID        |
| file_name   | Original filename   |
| file_url    | Public storage path |
| file_size   | Size of file        |
| uploaded_at | Timestamp           |

Then they are placed in:

```
/storage/v1/object/public/uploads/<user_id>/<filename>
```

# 🔷 **10. Troubleshooting File Upload Errors**

Below are common issues and how to fix them:

---

### ❌ **“Unsupported file format”**

Cause: File is PDF, ZIP, or image.
Fix: Upload only CSV or XLSX.

---

### ❌ **“Missing required columns”**

Example: sales file missing `date` or `sku_id`.
Fix: Add required columns.

---

### ❌ **“ParserError: Unexpected delimiter”**

Fix:

* Remove stray commas
* Save CSV in UTF-8 encoding

---

### ❌ **“No relevant file found”**

Cause: Filename lacks keywords.
Fix: Rename file to include “sales”, “inventory”, “product”, etc.

---

### ❌ **“No uploaded files found”**

Fix:

* Ensure you are logged in
* Re-upload files
* Check file size (< 50MB recommended)

DemandCast:

1. Downloads file from Supabase

7. Makes them available for training

# 🔷 **1. Introduction**

Once your data files are uploaded successfully, the next major step is **starting model training**.
DemandCast allows you to trigger multiple machine-learning pipelines together:

* Demand Forecasting
* Lead Time Estimation
* Stockout Prediction
* Promotional Effectiveness
* Pricing Elasticity
* RAG Embeddings Generation

All these models run **asynchronous background jobs** using RQ workers, allowing you to continue using the platform while your models train.

This document explains exactly how to start training, how the system works, and what you should expect.

---

# 🔷 **2. What Happens When You Start Training?**

When you click **“Start Training”** in the UI:

### ✔ DemandCast:

1. Validates your uploaded data
2. Collects your selected model settings
3. Sends the configuration to the FastAPI backend
4. Backend launches **six parallel training jobs** using RQ
5. Stores job IDs in your Supabase `models` table
6. Continues working in the background
7. Updates your dashboard when runs finish

This allows seamless, non-blocking analytics.

---

# 🔷 **3. Requirements Before Training**

Before clicking the Start button, you must:

### ✔ Upload necessary files

At minimum:

* Sales File
* Inventory File
* Product File

Optional but highly recommended:

* Promo File
* Pricing File
* Vendor/Leadtime File
* Customer File

### ✔ Select model parameters

Each pipeline has configurable settings (e.g. forecast horizon, smoothing window, etc.)

### ✔ Ensure your authentication token is active

Training requires a valid user session.

---

```
Left Sidebar → Model Training
```

* Demand Forecast Model

Each section contains drop-downs, toggles, and inputs.

Horizon = 30 → forecasts next 30 days.

| Setting              | Meaning                               |

Smoothing = 7 → weekly smoothing.

| Setting          | Meaning                       |

## **5.4 Promotional Effectiveness Settings**

| Setting              | Meaning                               |

## **5.5 Pricing Model Settings**

| Setting           | Meaning                                    |

| Setting         | Meaning                  |
| --------------- | ------------------------ |

| Dataset Name    | Which documents to embed |

# 🔷 3. Understanding Demand Forecast Results

### **✔ 3.1 Forecast Curve**

You’ll see a line chart showing:

* Historical demand
* Forecasted future values
* Upper/lower prediction intervals (if applicable)

**Interpretation Tips**:

* A widening cone means increasing uncertainty.
* Sharp spikes usually reflect actual demand seasonality (weekly/monthly cycles).
* A flat forecast may indicate insufficient historical data.

---

### **✔ 3.2 Metrics Summary**

You’ll find key metrics like:

* **MAE** (Mean Absolute Error)
* **RMSE** (Root Mean Squared Error)
* **R² Score**
* **MAPE** (optional)

**Interpretation:**

| Metric | Good       | Average | Poor |
| ------ | ---------- | ------- | ---- |
| MAE    | Low (<10%) | Medium  | High |
| RMSE   | Low        | Medium  | High |
| R²     | >0.8       | 0.5–0.8 | <0.5 |

---

### **✔ 3.3 SKU-Level Breakdown**

SKU forecasts include:

* Predicted sales
* Trend direction
* Seasonal patterns
* Volatility levels

**Interpretation Example**:

* If SKU A shows rising trend → reorder more
* If SKU B shows erratic movement → check supply consistency

---

# 🔷 4. Understanding Lead Time Results

### **✔ 4.1 Supplier Lead Time Distribution**

Displayed as:

* Histogram
* Box plot
* PDF curve

Interpretation:

* Long tails indicate unreliable suppliers
* Narrow bell shape indicates consistent deliveries
* Multiple peaks may reflect multiple vendors

---

### **✔ 4.2 Lead Time Summary Stats**

Includes:

* Average lead time
* Median
* Variance
* Worst-case lead time
* Supplier reliability score

**Interpretation:**

* Large variance → adjust safety stock
* High worst-case → avoid stockouts using buffer inventory

---

### **✔ 4.3 Supplier Scorecard**

Each vendor receives a reliability index (0–100).

Interpretation:

* > 80 excellent
* 60–80 moderate
* <60 risky supplier

---

# 🔷 5. Understanding Stockout Model Results

### **✔ 5.1 Stockout Probability Table**

Each SKU-location pair shows:

| SKU | Location | Probability | Risk Level | Expected Units Short |
| --- | -------- | ----------- | ---------- | -------------------- |

**Interpretation:**

* **>0.7** → High risk
* **0.4–0.7** → Medium
* **<0.4** → Low

Use high-risk SKUs for priority replenishment.

---

### **✔ 5.2 Confusion Matrix**

Shows model accuracy.

Interpretation:

* High FN → the model is missing stockouts → risky
* High FP → too many false alarms → refine thresholds

---

### **✔ 5.3 Recommendation Engine**

You may see suggestions like:

* “Increase safety stock for SKU P001 at Store L3.”
* “Supplier X delay increases stockout probability.”

---

# 🔷 6. Understanding Promotional Effectiveness Results

### **✔ 6.1 Uplift Curve**

Shows:

* No-promo scenario
* Actual promo demand
* Expected baseline

**Interpretation:**

If uplift is positive → promo worked.
If uplift is negative → promo failed or cannibalized other SKUs.

---

### **✔ 6.2 Incremental Revenue**

Displayed as:

```
Incremental Revenue = (Promo Sales - Baseline Sales) × Price
```

Interpretation:

* High incremental revenue → profitable promotion
* Negative → loss-making promo

---

### **✔ 6.3 Discount Sensitivity Charts**

Shows correlation between discount % and sales increase.

Interpretation:

* Steep slope → users very discount sensitive
* Flat → discount has no effect

---

### **✔ 6.4 Lookback Window Analysis**

Your selected lookback window affects baseline.
Larger lookback → more stable baseline
Shorter lookback → more responsive to recent changes

---

# 🔷 7. Understanding Price Elasticity Results

### **✔ 7.1 Elasticity Curve**

Shows demand response to price changes.

Interpretation:

* Curve downward → normal demand behavior
* If curve is flat → demand is price-insensitive
* If curve steepens → risk of volume drop

---

### **✔ 7.2 Optimal Price Point**

Computed using:

* Price elasticity
* Revenue maximization
* U-shaped responsiveness

Interpretation:

* Optimal price is where **revenue is maximized**, not where demand is highest.
* If optimal price > current price → underpricing issue
* If optimal price < current price → price too high

---

### **✔ 7.3 Cross-Elasticity Matrix**

Shows dependence of SKUs on each other.

Interpretation:

* Positive cross elasticity → substitutes
* Negative → complements

# 🔷 10. Common Interpretation Mistakes (Avoid Them)

### ❌ Over-reacting to short-term spikes

Always rely on trend + seasonality.

---

### ❌ Using stockout probabilities without considering leadtime

Probability must be matched with supplier reliability.

---

### ❌ Misreading optimal price as “only price to use”

Optimal price is model-based, but business constraints matter.

---

### ❌ Assuming promotional uplift means profit

Higher volume ≠ Higher revenue
Always check incremental margin.

---

### ❌ Expecting 100% accuracy

No model provides perfect predictions.
Interpret probabilistically.

### **Q: Why is promo uplift negative?**

* Promo too small
